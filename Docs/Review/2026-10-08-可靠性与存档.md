# 第一完善方向：可靠性与存档

日期：2026-10-08。环境：Unity 6000.5.10f1、macOS。对应[六项完善计划](../Plan/游戏完善计划.md)的第 1 项。

## 完成内容

- 25 种物品使用资产 `.meta` GUID 作为持久 ID，背包记录只保存 ID 与数量，消除 Unity 临时 instanceID 在重启后失效或错配的问题。进入 Play Mode、构建前自动生成并校验物品目录。
- 背包、武器、盾牌、饰品、商店库存各用固定存档键；人物、周目、场景和交互物状态继续保留原有保存职责。
- 记录增加版本、类型、SHA-256 校验和上一份备份。读档先校验，失败尝试备份；物品 ID、数量或槽位不合法时整份背包拒绝加载，避免只改了一半。
- 新游戏仅重置本游戏当前存档，使用新的存档命名空间隔离旧记录。即使记录索引损坏也不会复活上一局背包；不再调用 `PlayerPrefs.DeleteAll()`，保留其他设置和旧格式数据。
- 装备恢复与手动换装分开，刷新 UI 不再把已读入的武器搬回背包；形态模型替换立即脱离旧模型，再延迟销毁，避免装备挂到即将销毁的节点上。
- 继续游戏先恢复周目，再加载场景，交互物才能读到正确周目的状态；跨场景后建立目标场景检查点；胜利后保存下一轮的 Main 场景。
- 独立程序测试发现 Polybrush 读取恢复网格时报错，为场景及 prefab 中实际引用的 20 个源网格启用读取。保留原几何和顶点色，代价是这些网格保留 CPU 数据副本。修正相关恢复资产内部名称与文件名不一致的导入警告。

## 兼容边界与维护

1. 旧背包只保存临时 instanceID，无法可靠反推出原物品；原始 PlayerPrefs 记录保留，不猜测映射。无法恢复时使用初始化数据并输出说明。可以验证的旧普通数据仍尝试读取；空旧背包可安全读取。
2. 这是本机 PlayerPrefs 存档，校验用于发现损坏，不提供加密、反作弊、云同步或跨设备迁移。
3. 备份按单条记录维护，不等于所有记录一次性事务；不能承诺保存过程中断电时整个检查点全部一致。只有通过外层校验的先前主记录才轮换为备份，读档仍会执行内容验证；主、备均不可用时保留原记录并使用当前初始化数据。
4. 必须随物品资产一起保留 `.meta`；改显示名称、移动资源不会改变 ID，删除后重建 `.meta` 会变成新物品。增加物品后目录在 Play/构建前重建，直接修改槽位总数需要另行实现存档迁移。
5. 测试使用 `CodexIsolatedValidation` 下两个独立产品标识，与正式 `xhy Studio / 再来一次` 的存档隔离，没有读取或修改用户真实游戏存档。

实现位于 `Assets/Scripts/Persistence/`、`SaveManager`、`ItemCatalog`、`ItemCatalogBuilder` 及装备/场景控制脚本。测试源在 `Tools/Validation/`，独立程序测试入口只临时放入隔离工程，正式构建前移除。原始修改前文件保留于 `Builds/BeforeSaveReliability-20261008/`。

复测应在 `Builds/ResourceRepairCandidate` 或新的完整隔离副本执行；编辑器测试产品标识为 `OneMoreTimeSaveReliabilityChecks`，按顺序运行 `SaveReliabilityChecks.Write` 和 `Read`（不传 `-quit`，测试完成主动退出）。独立程序测试由 `SaveTestBuild.Build` 生成产品标识 `OneMoreTimeSavePlayerChecks`，分别用 `-saveCheckMode write/read` 启动，二者使用相同的 `-saveCheckOutput` 绝对路径。测试有产品标识保护，勿修改保护以在正式工程运行。

正式包：[OneMoreTime.app](../../Builds/Mac/OneMoreTime.app)。正式包不含自动存档测试入口；独立运行验证使用同一运行时代码的隔离标识测试构建。
