# Unity 6 兼容修复记录

## 当前结论

已完成可验证的代码与依赖兼容修复。在 Unity **6000.5.10f1** 的独立临时工程副本中编译成功退出，最终 **C# 编译错误 0、编译警告 0**，对象查找兼容性检查通过。

**这不等于整个工程已达到 Console 零错误、零警告。** 原仓库缺少 Assets/AssetsPack，目前仍有 **276 个资源 GUID** 无法在工程和已安装依赖中解析。Unity 实际导入报告了缺失预制体；因此没有进行完整 Play Mode 或通关验收，不能保证原功能和视觉效果全部恢复。

## 已完成

1. 按用户指定保留 Unity 6000.5.10f1，升级存在兼容错误的依赖。Cinemachine 保留 2.x 系列（2.10.7），没有迁移为 Cinemachine 3。URP 17.5.0、uGUI 2.5.0 对应当前编辑器；TextMeshPro 使用 uGUI 内置实现。
2. Polybrush 1.2.1 仍有过时对象 ID 接口，保留并嵌入 `Packages/com.unity.polybrush`，修复对象 ID 与场景查询 API。未删除绘制工具。不可序列化的 GPU 缓存及元组缓存明确标为 NonSerialized；这些字段原本就不被 Unity 序列化，不是屏蔽警告。
3. 从 Git 原始内容正确解码 **38 个 GBK/GB18030 脚本**，保存为 UTF-8 BOM。恢复被 Unity 自动升级误解码的中文分支和道具名。仅编码变化的脚本没有修改解码后的文本。
4. 将刚体 velocity 更新为 linearVelocity。对象查询通过 `LegacyObjectLookup` 兼容层保留旧查询顺序，而不是任意选择对象。该兼容层按当前 Unity 实现的低 32 位旧 InstanceID 排序；以后再升级 Unity 大版本应重跑兼容检查。
5. 对运行时字典和拖拽临时状态加 NonSerialized，消除新序列化分析器的有效警告，保留原先运行态行为。
6. 恢复丢失的 QuickOutline 组件。其原脚本 GUID `5fea29bb7c508c244a1f805a5fd3fc4d` 与现有敌人预制体完全匹配；保留该 GUID，无需修改预制体引用。脚本逻辑从自己的 Windows 成品恢复，原着色器和元数据从上游开源包恢复，保留许可证。
7. 为 QuickOutline 增加空网格检查，修复原模型缺失时 OnValidate/Bake 导致的空引用。缺失模型仍由资产诊断显式报告，未用空对象代替。
8. 添加 Editor-only 文件诊断工具；编辑器成功编译并加载后，写入 `Logs/ProjectDiagnostics/state.json`。不自动进入 Play Mode，不修改关卡。创建 `Logs/ProjectDiagnostics/refresh.request` 可请求编辑器刷新。诊断工具不会进入游戏构建。

## 原资源恢复调查

用户确认原完整工程没有保存在其他位置，仅保留 GitHub 仓库。Git 历史中未找到 AssetsPack。

使用 AssetRipper 2.0.0 将自己的 Windows 成品导出至 `Builds/RecoveredOriginal`，用于调查和保存可恢复内容。导出包含模型、贴图、场景及反编译脚本，但不是可直接替换原工程的完整源资源：

- 导出资产与缺失引用的原 GUID 没有匹配，直接导入不能修复原场景引用。
- 部分构建元数据解析异常。
- 着色器导出为 `DummyShaderTextExporter` 占位内容；直接使用会改变画面。
- 反导出场景不能保证原编辑结构、预制体继承与原编辑器资源完整保留。

因此保留该导出在 Builds 隔离目录，没有覆盖工程。QuickOutline 是已经能确认原身份并恢复的一项例外。

当前缺失引用清单：`RepairBaseline/missing-asset-references-after.json`。真实例子包括 Stone_Wall、HouseBase_03_LITE、Fence_02、Chest 的预制体父级等。

要达到“全部错误警告消除，且原功能不变”，仍需要恢复相应原资源包及其元数据，或开展逐项资产重建、映射和完整运行对照验证。当前条件下不能承诺后者与原版完全一致。
